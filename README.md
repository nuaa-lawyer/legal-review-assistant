## 🎯 项目概述

**法审助手**是一款面向产品经理和法务人员的AI合规审查系统。输入产品功能描述（如"社交App允许用户查看附近100米内其他用户位置"），系统自动输出结构化的合规风险报告，包含：风险点识别、法规依据匹配、修改建议生成。

### 核心亮点

- **规则 + 语义混合召回**：法律专业判断固化为规则表（按风险领域/行业强制召回核心条款），与 `bge-large-zh` 语义检索互补，解决"立法目的条款挤占 Top-K"的检索通病
- **决策化输出**：报告不止罗列风险，而是给出「风险等级 + 上线建议 + P0/P1/P2 整改清单」，可直接交研发执行
- **可量化的精准度**：内置 24 场景标注评测集，一键对比「裸大模型 / 单流水线 RAG / 多 Agent」的核心条款召回率与幻觉率
- **持续学习闭环**：审查结果与用户反馈全量落盘，👎 反馈自动沉淀为回归评测用例，👍 反馈提炼为 few-shot 判断口径
- **知识库增量更新**：`tools/sync_knowledge_base.py` 一条命令完成"新法规入库 + 数据质量体检 + 变更留痕"
- **RAG架构**：检索增强生成，确保每条风险分析都有真实法规依据，杜绝大模型"幻觉"
- **多Agent协作**：分类Agent → 检索Agent → 报告Agent，三个独立LLM调用分工协作
- **零成本运行**：使用免费API（SiliconFlow + DeepSeek），学生友好

## 🏗️ 技术架构

```
用户输入
   │
   ▼
┌─────────────────────────────────────────────────┐
│  🔍 Agent 1: 风险分类器 (RiskClassifier)         │
│  识别: 数据类型 | 处理行为 | 风险领域 | 风险等级  │
│  输出: 结构化JSON分类结果                        │
└─────────────────────┬───────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────┐
│  📚 Agent 2: 法规检索器 (LegalRetriever)         │
│  多角度查询生成 → 语义向量检索 → LLM精选+适用性分析│
│  输出: Top-5法条 + 适用原因                      │
└─────────────────────┬───────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────┐
│  📝 Agent 3: 报告生成器 (ReportGenerator)        │
│  汇总分类结果 + 法条依据 → 结构化合规报告         │
│  输出: 风险表格 | 修改建议 | 总结                │
└─────────────────────┬───────────────────────────┘
                      │
                      ▼
              结构化合规风险报告 (Markdown)
```

### 技术栈

| 组件        | 方案                              | 说明                  |
| --------- | ------------------------------- | ------------------- |
| LLM       | DeepSeek-V3                     | 中文法律文本理解和生成，极低成本    |
| Embedding | bge-large-zh-v1.5 (SiliconFlow) | 1024维中文语义向量，免费额度    |
| 向量检索      | NumPy + 余弦相似度                   | 零依赖，适合MVP规模         |
| 法规处理      | python-docx                     | 自动解析Word文档，按条款拆分    |
| 前端        | 自定义HTML + Streamlit             | 本地零依赖 / 云端展示        |
| Agent框架   | 自实现编排器                          | 轻量级，无需LangChain等重依赖 |

## 🚀 快速开始

### 1. 环境准备

```bash
pip install python-docx numpy openai python-dotenv
```

### 2. 配置API Key

```bash
cp .env.template .env
# 编辑 .env，填入 DeepSeek API Key 和 SiliconFlow API Key
```

### 3. 构建法规索引

```bash
python main.py --build
# 解析Word法规 → 生成向量 → 保存索引
```

### 4. 启动服务

```bash
# 本地Web界面 (零依赖)
python src/ui/server.py
# 浏览器打开 http://localhost:8080
```

## 🧪 定量评测（可复现）

```bash
# 全量评测：裸大模型 vs 单流水线RAG vs 多Agent（24 场景，覆盖 12 个行业）
python eval/run_eval.py

# 快速冒烟
python eval/run_eval.py --limit 2 --configs multi

# 只看指定场景
python eval/run_eval.py --ids C01,C03 --configs baseline,multi
```

产出：`eval/results/<时间戳>/summary.md`（汇总表）、`detail.csv`（逐用例明细）、  
`reports/<配置>/*.md`（原始报告，可人工复核）、`metrics.json`。

指标口径：核心条款召回率（人工标注的每场景 2 条必备依据命中比例）、全量条款召回率、  
编造条款数（引用了知识库中不存在的条款号）、引用精准率、可信报告率、耗时与成本。

### 评测结果（24 场景 × 3 配置，2026-10-13）

| 配置             | 核心条款召回率    | 全量条款召回率    | 平均引用数 | 引用精准率      | 编造条款/份 | 无编造报告率  | 可信报告率     | 平均耗时  | 平均成本    |
| -------------- | ---------- | ---------- | ----- | ---------- | ------ | ------- | --------- | ----- | ------- |
| 裸大模型（无知识库）     | 0.8333     | 0.7847     | 19.6  | 0.1222     | 1.0    | 0.5833  | 0.2917    | 12.4s | ¥0.016  |
| 单流水线 RAG       | 0.7083     | 0.639      | 7.8   | 0.2467     | 0.042  | 0.9583  | 0.5       | 9.2s  | ¥0.0137 |
| **多 Agent 协作** | **0.9375** | **0.9167** | 10.7  | **0.2508** | **0**  | **1.0** | **0.875** | 14.4s | ¥0.0288 |

结论：规则+语义混合召回 + 多 Agent 精选，使核心条款召回率达到 93.8%（裸大模型 83.3%），  
可信报告率（核心依据全覆盖且零编造）达 87.5%（裸大模型 29.2%），  
且 24 份报告零编造条款（裸大模型平均每份编造 1 条）；引用精准率为裸大模型的 2 倍。

## 🗂 知识库更新（新法规入库）

```bash
python tools/sync_knowledge_base.py            # 体检：新增/修正/最新 逐文件报告
python tools/sync_knowledge_base.py --apply    # 增量向量化并合并入库
python tools/sync_knowledge_base.py --raw-dir "E:/法条" --apply
```

支持 docx / pdf / txt / md；只对新增与修正条款调用 Embedding（省钱），  
自动写入 `processed/kb_manifest.json` 与 `feedback/update_log.jsonl` 留痕。
