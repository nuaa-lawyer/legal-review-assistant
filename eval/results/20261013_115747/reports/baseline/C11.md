# 智能音箱持续监听与云端上传功能合规风险审查报告


## 🔴 高风险项

| 风险点 | 违反法规 | 具体条款 | 风险说明 |
|--------|----------|----------|----------|
| 持续监听环境声音并实时上传云端，未取得用户明示同意 | 《中华人民共和国个人信息保护法》 | 第十三条、第十四条、第十七条 | 持续采集环境音频属于个人信息处理行为，且音频信息可识别自然人身份，属于敏感个人信息。必须取得用户**单独同意**并明确告知处理目的、方式、范围。默认开启持续监听并上传，构成未经同意处理个人信息。 |
| 环境音频可能涉及第三方（非用户）的语音信息，未取得第三方同意 | 《中华人民共和国个人信息保护法》 | 第十三条、第二十三条 | 智能音箱持续监听会采集到访客、家庭成员等非设备用户的语音，这些人未被告知也未同意其个人信息被采集和上传，构成对第三方个人信息的非法处理。 |
| 录音实时上传云端进行语义分析，超出"改进唤醒准确率"所必需的最小范围 | 《中华人民共和国个人信息保护法》 | 第六条（最小必要原则） | 改进唤醒准确率仅需提取声学特征（如音调、音色模式），无需上传完整录音内容进行语义分析。上传完整录音并做语义分析明显超出声明目的所需范围，违反最小必要原则。 |
| 音频数据（含生物识别信息）上传至云端，未进行个人信息保护影响评估（PIA） | 《中华人民共和国个人信息保护法》 | 第五十五条、第五十六条 | 处理敏感个人信息、利用个人信息进行自动化决策、向境外提供个人信息等情形，必须事前进行个人信息保护影响评估并记录处理情况。持续上传音频至云端属于必须做PIA的情形。 |
| 未明确告知数据存储期限、删除机制及用户撤回同意的方式 | 《中华人民共和国个人信息保护法》 | 第十七条、第四十七条 | 法律要求告知个人信息保存期限及到期后的处理方式，并提供便捷的撤回同意和删除途径。产品功能描述中未见相关机制。 |
| 若云端服务器位于境外或使用境外云服务，构成数据出境 | 《中华人民共和国个人信息保护法》 / 《数据出境安全评估办法》 | 个保法第三十八条、第三十九条；数据出境办法第四条 | 音频数据含敏感个人信息，出境需通过安全评估、认证或签订标准合同，并取得用户单独同意。 |
| 持续监听可能构成对住宅内私人活动的侵扰 | 《中华人民共和国民法典》 | 第一千零三十二条、第一千零三十三条 | 自然人享有隐私权，任何组织或个人不得以刺探、侵扰等方式侵害他人隐私。持续监听家庭环境声音可能构成对私人生活安宁和私密活动的侵扰。 |
| 若涉及未成年人语音采集，未取得监护人同意 | 《中华人民共和国个人信息保护法》 / 《未成年人网络保护条例》 | 个保法第三十一条；未保条例第四十三条 | 处理不满十四周岁未成年人个人信息，须取得父母或其他监护人同意，并制定专门处理规则。家庭环境中极易采集到未成年人语音。 |

## 🛠️ 整改清单

| 优先级 | 整改项 | 具体操作 | 法规依据 |
|--------|--------|----------|----------|
| P0 | 取得用户单独同意 | 首次开机时弹窗告知音频采集目的、方式、范围、存储期限，取得用户**单独同意**（不得默认勾选），并提供拒绝选项 | 个保法第十三条、第十四条、第十七条 |
| P0 | 将唤醒词检测限定在本地完成 | 唤醒词识别在设备端完成，仅唤醒后的指令音频上传云端，避免持续上传环境音 | 个保法第六条（最小必要原则） |
| P0 | 开展个人信息保护影响评估（PIA） | 对音频采集、上传、语义分析全流程进行PIA，形成评估报告并留存至少三年 | 个保法第五十五条、第五十六条 |
| P0 | 明确数据存储期限与删除机制 | 设定音频数据最长存储期限（如30天），到期自动删除；提供用户一键删除历史音频的功能 | 个保法第十七条、第四十七条 |
| P0 | 若涉及数据出境，完成合规路径 | 评估是否出境；如出境，通过安全评估/标准合同/认证，并取得单独同意 | 个保法第三十八条、第三十九条；数据出境办法第四条 |
| P1 | 提供便捷的关闭/撤回同意选项 | 在App和设备端提供一键关闭持续监听功能的入口，关闭后基本功能仍可用 | 个保法第十五条、第十六条、第四十四条 |
| P1 | 传输与存储加密 | 音频上传使用TLS 1.2+加密传输；云端存储使用AES-256等加密，密钥单独管理 | 个保法第五十一条；网安法第四十二条 |
| P1 | 建立泄露应急与通知机制 | 制定数据泄露应急预案，发生泄露后72小时内通知监管部门并告知受影响用户 | 个保法第五十七条；网安法第四十二条 |
| P1 | 未成年人保护机制 | 若识别到未成年人语音，制定专门处理规则并取得监护人同意；提供儿童模式 | 个保法第三十一条；未保条例第四十三条 |
| P2 | 完善隐私政策告知 | 以显著方式、清晰易懂语言告知处理规则，不得使用晦涩法律术语堆砌 | 个保法第十七条 |
| P2 | 提供数据查阅复制途径 | 在App中提供用户查阅、复制其音频数据的功能 | 个保法第四十五条 |
| P2 | 明确目的限制，禁止目的外使用 | 在隐私政策和内部制度中明确语义分析结果仅用于改进唤醒准确率，不得用于用户画像或广告推送 | 个保法第六条、第十四条 |


## ⚠️ 总结

本产品功能"持续监听环境声音并实时上传云端进行语义分析"存在**系统性合规缺陷**，核心问题在于：

1. **合法性基础缺失**：持续监听+上传+语义分析的全链路处理，未取得用户单独同意，也未对第三方（访客、家庭成员）的语音采集建立合法依据，违反《个人信息保护法》第十三条、第十四条。

2. **违反最小必要原则**：改进唤醒准确率仅需声学特征，无需上传完整录音做语义分析，处理范围明显超出声明目的，违反《个人信息保护法》第六条。

3. **敏感个人信息保护不足**：音频（含声纹）属于敏感个人信息，未做PIA、未加密、未告知存储期限，违反第五十一条、第五十五条。

4. **隐私权侵扰风险**：持续监听家庭环境可能构成《民法典》第一千零三十二条、第一千零三十三条下的隐私权侵害。

5. **数据出境风险**：若使用境外云服务，未完成数据出境合规路径，违反第三十八条、第三十九条。

**建议**：在完成上述P0级整改前，**不建议该功能上线**。核心整改方向为：将唤醒词检测限定在本地、仅上传唤醒后的指令音频、取得单独同意、完成PIA、建立数据生命周期管理机制。若无法将语义分析限定在必要范围内，应考虑取消云端语义分析功能或改为端侧处理。
