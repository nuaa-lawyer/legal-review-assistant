# [baseline] C02 生物识别实名

**输入**: 用户上传身份证照片和人脸照片后，系统自动进行实名认证并永久保存到数据库中

**ground truth**: 中华人民共和国个人信息保护法第二十九条, 中华人民共和国个人信息保护法第二十八条, 中华人民共和国反电信网络诈骗法第二十一条

# 合规风险审查报告

> **审查对象**：用户上传身份证照片 + 人脸照片 → 系统自动实名认证 → **永久保存**至数据库
> **审查视角**：个人信息保护、数据安全、网络安全、征信/反洗钱、消费者权益
> **审查日期**：以实际出具日为准


## 🔴 高风险项

| 风险点 | 违反法规 | 具体条款 | 风险说明 |
|---|---|---|---|
| **"永久保存"身份证照片、人脸照片** | 《中华人民共和国个人信息保护法》 | 第19条：除法律、行政法规另有规定外，**个人信息的保存期限应当为实现处理目的所必要的最短时间** | "永久保存"直接违反最短必要期限原则。身份证照片、人脸信息属于敏感个人信息，永久保存意味着无限期风险敞口，一旦泄露影响不可逆。 |
| **处理人脸信息未单独取得同意** | 《个人信息保护法》 | 第29条：处理敏感个人信息应当取得个人的**单独同意**；法律、行政法规规定处理敏感个人信息应当取得书面同意的，从其规定 | 人脸信息属于生物识别信息，是敏感个人信息。若仅在用户协议中"打包同意"，未设置独立弹窗/单独勾选，则同意无效。 |
| **处理敏感个人信息未履行告知义务（增强告知）** | 《个人信息保护法》 | 第30条：处理敏感个人信息，应当向个人告知**处理敏感个人信息的必要性以及对个人权益的影响** | 仅告知"用于实名认证"不足，必须说明为何必须采集人脸、不提供的后果、对个人权益的具体影响。 |
| **未进行个人信息保护影响评估（PIA）** | 《个人信息保护法》 | 第55条：处理敏感个人信息、利用个人信息进行自动化决策等情形，应当**事前进行个人信息保护影响评估**，并对处理情况进行记录 | 人脸识别 + 自动化实名认证属于强制评估情形。未做PIA即上线，属程序性违法。 |
| **未取得个人信息处理者的合法性基础（单独同意+必要性）** | 《个人信息保护法》 | 第13条、第28条、第29条 | 实名认证场景下，若无法证明"为履行法定职责或法定义务所必需"，则必须取得单独同意；且需满足"特定目的+充分必要性"。 |
| **人脸信息存储与传输未满足更高安全要求** | 《数据安全法》 / 《个人信息保护法》 | 《个保法》第51条：采取加密、去标识化等安全技术措施；《数据安全法》第27条：建立健全全流程数据安全管理制度 | 人脸照片原图存储、未加密、未去标识化、未与身份信息分离存储，均构成高风险。 |
| **可能违反"最小必要"原则采集人脸** | 《个人信息保护法》 | 第6条：处理个人信息应当具有明确、合理的目的，并应当与处理目的**直接相关**，采取对个人权益**影响最小的方式** | 若实名认证可通过身份证OCR+公安库比对完成，则强制采集人脸可能超出必要范围（除非业务确需活体检测）。 |
| **未提供删除权/撤回同意机制** | 《个人信息保护法》 | 第15条：个人有权撤回同意；第47条：处理目的已实现、保存期限届满等情形，应当**主动删除** | "永久保存"实质上剥夺了用户的删除权和撤回同意权，违反第47条。 |
| **未制定个人信息泄露应急预案** | 《个人信息保护法》 | 第51条、第57条：发生泄露应立即采取补救措施并通知履行个人信息保护职责的部门和个人 | 永久保存大量敏感信息，泄露风险极高，若无应急预案，违法。 |
| **可能违反《网络安全法》等级保护要求** | 《网络安全法》 | 第21条：采取监测、记录网络运行状态、网络安全事件的技术措施，并留存日志不少于6个月；第31条：关键信息基础设施重点保护 | 存储大量公民身份证、人脸信息的系统，通常需通过等保三级，未定级/未测评即运营属违法。 |


## 🟡 中风险项

| 风险点 | 违反法规 | 具体条款 | 风险说明 |
|---|---|---|---|
| **未明确告知保存期限** | 《个人信息保护法》 | 第17条：告知处理目的、方式、**保存期限** | 用户协议中若未写明"保存X年"或"至账户注销后X天"，仅写"永久保存"，告知不完整。 |
| **自动化实名认证未告知自动化决策逻辑** | 《个人信息保护法》 | 第24条：利用个人信息进行自动化决策，应当保证决策的**透明度和结果公平、公正** | 系统自动比对、自动通过/拒绝，若未告知用户算法逻辑及拒绝后的救济途径，存在合规瑕疵。 |
| **未区分"身份信息"与"人脸信息"的存储策略** | 《个人信息保护法》 | 第51条：对个人信息实行**分类管理** | 身份证号、姓名属于一般敏感信息，人脸属于生物识别信息，二者应分类分级存储，不应混存于同一明文库。 |
| **未与第三方（如公安库、OCR服务商）签订数据处理协议** | 《个人信息保护法》 | 第21条：委托处理个人信息，应当与受托人约定处理目的、期限、方式等，并进行监督 | 若调用第三方实名认证接口，未签DPA（数据处理协议），责任不清。 |
| **未提供便捷的注销/删除入口** | 《个人信息保护法》 | 第47条、第50条：个人行使权利的申请，应当提供便捷的申请受理和处理机制 | 若用户无法自助删除或注销后仍"永久保存"，违法。 |
| **未对未成年人身份进行识别与特殊保护** | 《个人信息保护法》 | 第31条：处理不满十四周岁未成年人个人信息，应当取得父母或其他监护人同意，并制定专门处理规则 | 若用户群体可能包含未成年人，未做年龄识别即采集人脸，违法。 |
| **日志留存不足** | 《网络安全法》 | 第21条第（三）项：采取监测、记录网络运行状态、网络安全事件的技术措施，并按照规定**留存相关的网络日志不少于六个月** | 实名认证操作日志、访问日志若未留存6个月，不合规。 |
| **未进行数据出境安全评估（如涉及境外服务器）** | 《个人信息保护法》 / 《数据出境安全评估办法》 | 《个保法》第38条、第40条；《数据出境安全评估办法》第4条 | 若数据库部署在境外或使用境外云服务，需申报安全评估。 |


## 🛠️ 整改清单

| 优先级 | 整改项 | 具体操作 | 法规依据 |
|---|---|---|---|
| **P0** | 取消"永久保存"，设定最短必要期限 | 明确保存期限（如：实名认证通过后保存至账户注销后30天；或按反洗钱要求保存5年，但需有法定依据）。到期自动删除或匿名化。 | 《个保法》第19条、第47条 |
| **P0** | 人脸信息单独同意 | 在采集前弹出独立同意框，明确告知：处理人脸信息的必要性、对个人权益的影响、保存期限、拒绝后果。不得默认勾选。 | 《个保法》第29条、第30条 |
| **P0** | 开展个人信息保护影响评估（PIA） | 对实名认证+人脸识别场景进行PIA，形成书面报告并留存至少3年。 | 《个保法》第55条、第56条 |
| **P0** | 人脸信息加密、去标识化、分离存储 | 人脸特征值加密存储，原始照片原则上不存储或加密后单独隔离存储；身份证号去标识化展示。 | 《个保法》第51条 |
| **P0** | 提供删除权、撤回同意、注销功能 | 在App/网站设置"撤回同意""删除个人信息""注销账户"入口，注销后按期删除。 | 《个保法》第15条、第47条、第50条 |
| **P1** | 完善隐私政策与告知 | 明确写出：处理目的、方式、保存期限、第三方共享情况、用户权利行使方式。 | 《个保法》第17条 |
| **P1** | 与第三方服务商签订数据处理协议 | 若使用OCR、公安比对、云存储，签订DPA，明确安全义务、审计权、删除义务。 | 《个保法》第21条 |
| **P1** | 完成等保定级备案与测评 | 存储大量敏感个人信息的系统，通常定级为等保三级，完成备案和测评。 | 《网络安全法》第21条、第31条 |
| **P1** | 建立泄露应急预案与通知机制 | 制定预案，发生泄露立即补救并通知监管部门和个人。 | 《个保法》第57条 |

| **P2** | 自动化决策透明度 | 告知用户自动化认证逻辑，提供人工复核渠道。 | 《个保法》第24条 |

| **P2** | 数据出境合规（如适用） | 若涉及境外存储/处理，申报安全评估或签订标准合同。 | 《个保法》第38条；《数据出境安全评估办法》第4条 |


## ⚠️ 总结

本产品功能存在**多项高风险合规缺陷**，核心问题集中在：

1. **"永久保存"直接违法**——《个人信息保护法》第19条明确要求最短必要期限，永久保存无任何法律依据，且放大了泄露风险。
2. **人脸信息处理程序严重不足**——未单独同意、未增强告知、未做PIA，属于《个保法》第29、30、55条的强制性要求，缺失即违法。
3. **用户权利被架空**——永久保存实质上剥夺了删除权、撤回同意权，违反第15、47条。
4. **安全措施与存储规模不匹配**——大量身份证+人脸原图若未加密、未分离、未定级，违反《个保法》第51条和《网络安全法》第21条。

**建议**：
- **立即停止"永久保存"策略**，改为"法定/约定最短期限+到期自动删除"。
- **上线前必须完成PIA、单独同意弹窗、加密存储、删除入口**四项P0整改。
- 若业务确需长期保存（如反洗钱5年），必须**有明确法律依据**，且仍需满足安全措施和用户权利保障要求。

> **合规底线**：人脸信息属于敏感个人信息中的生物识别信息，一旦泄露不可撤销。任何"永久保存"的设计，在现行法律框架下均**不可接受**。
